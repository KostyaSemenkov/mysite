# Китайские нейросети — инструкция редактору

## Что уже настроено

- Раздел: http://127.0.0.1:8002/china-ai/ . Поиск, фильтры компаний и 9 карточек на страницу.
- 16 настоящих материалов (по четыре от Kimi, Z.ai, Qwen, DeepSeek) импортированы в закрытую очередь. Первые русские изложения подготовлены при подключении, без платных API.
- Публикация только после ручного одобрения. До него пустой раздел — ожидаемое поведение.
- Почасовое задание Windows: `NEYRO-China-News-Hourly`. Работает в фоне, пока компьютер включён, не спит, есть интернет и пользователь вошёл в Windows. Блокировка экрана не мешает. После пропуска запуск выполняется при следующей доступности. Сайт может быть закрыт: сборщик запускается отдельно.
- Последние проверки и ошибки видны в админке, журнал также в `logs/china-news.log`.

## Первый вход

1. В Проводнике откройте папку `D:\gpt\ai_portal`.
2. Запустите `create-editor.cmd` двойным щелчком. Задайте логин и пароль. При вводе пароля символы в консоли не отображаются — это нормально. Email для локальной версии можно оставить пустым.
3. Откройте http://127.0.0.1:8002/admin/ и войдите с этими данными.
4. Выберите «Китайские нейросети — входящие новости».

Если сайт не открывается после перезагрузки компьютера, запустите `start-site.cmd`. Окно сервера нужно оставить открытым. Сборщик запускается по расписанию независимо от этого окна.

## Проверка и публикация

1. Откройте новость. Сверьте русский текст с оригиналом и ссылкой на официальный сайт. Дата публикации на сайте будет датой официального источника.
2. Ссылка «Открыть черновик» показывает будущий материал; доступ к ней есть только у пользователей с правом просмотра входящих новостей.
3. Если редактировали текст, сохраните запись, откройте предпросмотр и нажмите «Текст готов к проверке».
4. Когда готовы опубликовать, нажмите в предпросмотре «Одобрить и опубликовать». Это сразу разместит материал на сайте.
5. Новость появится в отдельном разделе и общей ленте. Повторное одобрение обновлённого материала использует ту же страницу, не создаёт дубль.

Первые 16 записей уже имеют статус «Готово к проверке». Можно сразу проверить их и выполнить шаг 4. После изменения текста шаг 3 обязателен.

Если оригинал или черновик изменился, пока вы читали страницу, действие не выполняется: появляется сообщение с просьбой обновить страницу и проверить актуальную версию. Такое же правило действует при сохранении правок в админке. Чтобы сохранить свою работу при конфликте, скопируйте введённый текст перед обновлением страницы.

В предпросмотре также доступны кнопка «Отклонить черновик» и предыдущая версия оригинала, если он менялся. Групповые действия в списке новостей по-прежнему доступны редактору.

«Отклонить» убирает материал из рабочего потока, но сохраняет запись, чтобы сборщик не приносил её повторно. Если новость уже была опубликована, отклонение нового варианта не удаляет старую публикацию. Снять её с сайта можно в разделе «Публикации», убрав отметку «Опубликовано».

## Как работает сбор

Источники фиксированы в коде; записи извне не могут заставить сборщик обращаться к произвольным адресам.

- Kimi: `https://www.kimi.com/en/blog/`, `https://platform.kimi.ai/blog`, журнал `https://platform.kimi.ai/blog/posts/changelog`.
- Z.ai: `https://docs.z.ai/release-notes/new-released` (официальный журнал выпусков; не весь исследовательский блог).
- Qwen: публичная лента сайта `https://qwen.ai/api/v2/article/retrieval?type=qwen_ai&language=en-US`; ссылки читателю ведут на `https://qwen.ai/blog?id=…`. Это чтение общедоступной ленты, не платный API модели. Старый архив page_config не используется вместо актуальных выпусков.
- DeepSeek: `https://api-docs.deepseek.com/updates/`, каждая датированная запись сохраняется отдельно.

Первый импорт берёт четыре последних подходящих материала каждого подключённого источника. Старый непринятый архив запоминается, чтобы последующие запуски не заполняли очередь старыми записями. Вакансии, акции, учебные руководства и отдельные исследования бенчмарков исключаются правилами по заголовкам. Эти правила не заменяют редакторскую проверку и могут потребовать уточнения для новых формулировок.

Сборщик проверяет подключённые ленты и ранее импортированные записи, пока они присутствуют в выдаче. Он не отслеживает все страницы документации и незаявленные правки каждой таблицы цен. При удалении записи из ленты опубликованный материал не удаляется автоматически.

Идентификатор публикации и отпечаток текста защищают от повторного импорта. Если оригинал изменился, появляется статус «Источник изменился» и сохраняется предыдущая версия. Русское изложение и уже опубликованный текст не перезаписываются автоматически. Нужно сверить изменения, исправить русский текст и повторно одобрить его.

Ошибки одного источника не останавливают остальные. При сбое сеть повторяется ограниченное число раз, ошибка видна в админке; зависшие запуски ограничены временем, параллельные сборщики блокируются.

## Перевод и стоимость

Платных запросов нет, ключей в проекте нет. Подписка Z.ai Coding Plan не используется сборщиком. Для новых материалов сохраняются официальный текст, дата и ссылка; статус — «Ожидает русского изложения». Заполните русский текст вручную или подключите отдельный API на следующем этапе. Без этого новые материалы автоматически переводиться не будут.

Официальное описание ограничений Coding Plan: https://docs.z.ai/devpack/faq . Общий API Z.ai — отдельный продукт: https://docs.z.ai/api-reference/introduction .

## Управление расписанием

В Windows откройте «Планировщик заданий» и найдите `NEYRO-China-News-Hourly`. Можно отключить, включить или запустить его вручную. Отключение отдельного источника доступно в админке через поле «Собирать новости».

Ручной сбор из PowerShell:

```powershell
cd D:\gpt\ai_portal
.\.venv\Scripts\python.exe manage.py import_china_news
```

Проверка конкретного источника: добавьте `--source kimi`, `--source zai`, `--source qwen` или `--source deepseek`.

Повторная установка расписания после перемещения проекта:

```powershell
.\scripts\install_news_task.ps1
```

Задание сохраняет абсолютный путь к текущему проекту. Перемещение требует переустановки задания с проверкой старого пути. Скрипт не заменяет чужую задачу с тем же именем.

## Перенос на Cloud.ru позднее

Сборщик не привязан к Windows: на Linux запускайте ту же команду Django через cron или systemd timer каждый час. Сначала выключите локальное задание, перенесите базу и настройки, затем включите серверное расписание, чтобы избежать двух независимых очередей. Выбор сервиса Cloud.ru и развёртывание ещё не выполнялись.

База до изменения структуры сохранена в `backups/`. Для текущего рабочего процесса регулярно сохраняйте резервные копии базы. Постоянная автоматическая резервная копия в этой версии не настраивалась.
